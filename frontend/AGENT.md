# AGENT.md — 前端设计准则

> 本文件是 AI Agent Workbench（核真 Veritas）前端设计与编码的**最高约束**。
> 任何页面、组件、交互的实现都必须先通过本文件的检查。与需求冲突时，先在此文件中修订原则，再动代码。

## 参考基准

参考 ChatGPT Desktop / DeepSeek Harness 类工作台的三张基准截图：

1. **工作台主视图**：顶部栏（任务名 + 状态 + 自主程度）｜左栏 Sessions / Active Agents / Workspace / Plugins｜中栏 Plan 步骤流 + Conversation｜右栏 Activity Stream。
2. **监督视图**：Activity Stream（时间线）与 Approval Queue（置信度 + Approve/Reject/Edit）并排。
3. **Build Canvas**：左侧 Build Plan + 对话历史，右侧 Live Preview 实时预览。

共同气质：**安静、克制、留白充足**。界面是 Agent 工作的「仪表间」，不是炫技场。

**宣传页附加准则**（在低噪音原则之上的让步）：
- 允许更大的字号层级（Hero 标题 clamp 32–52px）与少量滚动渐入动效（`prefers-reduced-motion` 时禁用）。
- 仍禁止：渐变横幅、霓虹发光、emoji 堆砌、自动播放轮播；色彩预算与状态色语义不变。
- 文案服务于「判断可复核」的核心卖点：可信/存疑/无法核实 + 证据 + 来源。

**部署（GitHub Pages）**：
- 仓库已含 `.nojekyll`，纯静态直接部署 frontend/ 目录内容。
- 推荐方式（frontend 为子目录）：`git subtree push --prefix frontend origin gh-pages`；或在仓库 Settings → Pages 选择 GitHub Actions 工作流。
- demo.html 带 `noindex`，SEO 权重集中到宣传页；两页共用 assets/icon.png 作为分享图与 favicon。

## 原则一：减少视觉噪音

1. **一屏一个焦点**。每屏只允许一个视觉重心（当前运行中的步骤 / 待审批卡片）。其余内容一律降级为灰阶层。
2. **色彩预算**：主色（蓝）仅用于「可点击」与「当前态」；状态色（绿/橙/红）只以 8px 圆点或细条出现，禁止大面积色块。中性灰占界面 ≥ 90%。
3. **文字分层**最多三级：正文 `#1f2329`、次要 `#6b7280`、辅助 `#9ca3af`。辅助信息（时间戳、token 数、版本号）一律用最小号灰字，不与正文抢读。
4. **边框为主、轻阴影为辅**：卡片使用细边框与统一的 `--shadow-card`；浮动层使用 `--shadow-float`。禁止大投影和彩色光晕。
5. **图标低饱和**：线性图标 14–16px，继承文字颜色；不使用彩色填充图标和 emoji 装饰。
6. **动效克制**：只做状态过渡（150–200ms ease-out），不做入场动画、不做回弹、不做常驻循环动画（运行中状态点除外）。

## 原则二：降低视觉存在感（Visual Quietness）

1. **容器感最小化**：优先用留白和细分隔线分组，能不用卡片就不用卡片；卡片圆角统一 8px，内边距统一 12–16px。
2. **次要操作不可见**：编辑、归档、展开详情等操作默认隐藏，hover 才出现；主操作每屏 ≤ 1 个实心按钮。
3. **表格与列表去装饰**：无斑马纹、无竖线，仅保留浅色横向分隔。
4. **状态可感知但不打扰**：Running 用蓝色呼吸圆点和简短文字，Failed 用红点和文字；不用横幅或弹窗轰炸。
5. **深浅双主题共用同一套布局**，深色主题同样遵守上述噪音约束（低对比灰阶、禁用发光）。

## 原则三：简洁为主

1. **信息密度适中**：每栏内容纵向节奏 8px 网格；段落间留白 ≥ 12px；能一行说清的不折两行。
2. **渐进披露**：Plan 步骤、工具调用、活动日志默认收起摘要行，点击展开完整输入/输出；Thinking 块默认折叠。
3. **文案即 UI**：按钮用动词（批准 / 拒绝 / 重放），状态用名词（Running / 待审批）；禁止解释用户已看见的内容的冗余文案。
4. **导航扁平**：视图切换 ≤ 5 个标签，右侧面板标签 ≤ 4 个；超过就合并，不堆叠导航层。
5. **空状态有教育意义**：一句话说明这里会出现什么 + 一个行动入口，不放插画占位。

## 原则四：交互以用户体验为主

1. **状态永远可见**：任务进度（n/m）、当前步骤、Agent 忙闲，用户任何时刻无需猜。
2. **危险与不可逆操作必须确认**：拒绝审批需二次确认；批准低置信度（<60%）操作时按钮自动降为次要色并提示风险。
3. **可撤销优于弹窗**：批准/拒绝后提供 5 秒内的「撤销」toast，而非阻断式确认框。
4. **键盘优先**：`Enter` 发送、`Esc` 暂停/接管（Escape Hatch 常驻右上）、`Tab` 顺序符合视觉顺序。
5. **置信度语言统一**：≥80% 绿、60–80% 橙、<60% 红；同一数值在步骤卡、审批卡、Confidence 面板中表现一致。
6. **反馈及时**：所有点击 100ms 内有视觉响应；加载超过 300ms 才显示 loading 态。

## 设计 Tokens（实现必须引用变量，禁止裸值）

```css
/* 颜色 */
--bg: #f7f8fa;          /* 页面底 */
--surface: #ffffff;     /* 卡片 */
--border: #e7e9ee;      /* 1px 细边框 */
--text: #1f2329; --text-2: #6b7280; --text-3: #9ca3af;
--accent: #2f6bed;      /* 仅：可点击 + 当前态 */
--ok: #22a06b; --warn: #e8930c; --danger: #e5484d;
--radius: 8px; --radius-sm: 8px;
/* 字体 */
系统栈（-apple-system / Segoe UI / PingFang SC / Microsoft YaHei）；
正文 13px / 行高 1.6；辅助 11px；标题 600 字重。
/* 间距 */ 8px 基准网格（4/8/12/16/24）
```

## 组件速查

| 组件 | 规则 |
|---|---|
| 步骤卡 | 序号方块 24px + 标题 + 状态徽章；状态色只染徽章与序号 |
| 工具调用卡 | `工具名(参数)` 单行 mono + 时长；结果折叠 |
| 审批卡 | 标题 + 影响说明 + 置信度细条 + 三按钮；置信度 <60% 时「批准」降级为描边样式 |
| 活动流 | 时间线圆点 8px + 灰字摘要；点击展开原文 |
| 输入框 | 单卡式，focus 时边框变主色，无阴影放大 |

## 禁止清单（Code Review 直接打回）

- ❌ 渐变横幅、霓虹发光、玻璃拟态滥用
- ❌ 每屏多个实心主按钮
- ❌ 未引用 token 的裸色值 / 裸字号
- ❌ 常驻循环动画（运行状态呼吸点除外）
- ❌ 用颜色 alone 传达状态（必须有点位/文字佐证，照顾色弱）
- ❌ 阻断式确认框替代可撤销 toast（不可逆操作除外）

## 2026 视觉执行补充

本项目的界面基准采用「安静的 Agent 控制台」：参考 ChatGPT Desktop、研究工作台和 Build Canvas 的共同结构，但不复制具体产品外观。

### 页面构成

1. 顶栏只承载品牌、当前任务、运行状态、自主程度和暂停 / 接管入口。
2. 左栏承载会话、Agent、工作区和插件，保持稳定宽度；中栏承载当前任务，是一屏唯一主焦点；右栏承载活动流、审批、看板和产物。
3. Build Canvas 复用相同顶栏和状态语言，左侧是步骤与对话历史，右侧是实时预览。
4. 窄屏隐藏左栏与右栏，保留中栏工作流；不得让三栏压缩成不可读的横向滚动区。

### 视觉语言

- 页面底色使用冷灰 `#f4f6f9`，内容面使用白色；边界使用 `#dfe4eb` 和 `#edf0f4`。
- 蓝色只表达当前态、链接、聚焦和主操作；绿 / 橙 / 红只表达运行、等待和失败。
- 状态优先用「圆点 + 文字 + 细条」表达，禁止只用颜色区分状态。
- 卡片圆角统一 8px，重复项目使用统一轻阴影；页面分区不套卡片，toast、菜单和弹层使用浮动层阴影。
- 图标优先使用线性图形或短文本标记；禁止在关键导航、审批卡和产物列表中使用 emoji。
- 标题采用紧凑的系统无衬线字体；时间、工具调用、版本号使用等宽字体，便于扫描和比对。

### 交互状态

- 主任务必须始终显示 `n / m` 进度、当前运行步骤和 Agent 忙闲状态。
- 状态颜色只有五种固定语义：蓝色 `--accent` 表示 Running / Doing / 当前选中；绿色 `--ok` 表示 Done / Success / 可信；橙色 `--warn` 表示 Review / 待审批 / 风险；红色 `--danger` 表示 Failed / Reject / 冲突；灰色 `--text-3` 表示 Pending / Idle / 未开始。
- 同一状态在顶部状态、步骤序号、标签、活动流圆点、Kanban 卡片左边线和置信度条中必须使用相同语义色。Running 不得使用成功绿，Done 不得使用主蓝。
- 审批卡固定包含影响说明、置信度细条和「批准 / 拒绝 / 编辑」三类动作；低于 60% 时批准按钮只能使用降级样式。
- 活动流默认显示摘要，工具输入 / 输出通过点击展开；新增记录从顶部插入且不打断用户当前阅读。
- 主题切换、暂停 / 接管、标签切换和插件开关必须保留键盘焦点样式；`Esc` 始终表示暂停 / 接管。
- 所有可逆动作优先使用带 5 秒撤销窗口的 toast，不用阻断式确认弹窗。
- 桌面端左右侧栏必须支持独立显示 / 隐藏；隐藏操作应回收对应网格空间，并通过按钮的 `aria-expanded`、标题和状态样式反馈当前状态。

### 实现约束

- 所有颜色、圆角、字号和阴影必须来自 `styles.css` 顶部 token；新增组件先扩展 token，再写选择器。
- 卡片圆角统一为 `8px`，普通卡片统一使用一层轻阴影 `--shadow-card`；不得在不同模块临时发明新的圆角或阴影。
- 工作台卡片之间至少保留 `20px` 间距。Build Canvas 应优先把水平空间交给 Live Preview，左侧计划栏控制在约 `220px`，外层导航与状态栏保持窄而稳定。
- 优先使用现有 HTML 结构和类名，避免为纯视觉变化引入新的状态逻辑。
- 任何新增界面都要同时检查 1440px 桌面、1180px 窄桌面和 680px 移动断点，确保文字不溢出、按钮可触达、主焦点仍然清晰。
